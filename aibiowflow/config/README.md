# AIBioFlow Configuration Files

## 概述 (Overview)

本目录 (`aibiowflow/config/`) 用于存放 AIBioFlow 系统各个模块的配置文件。通过将配置外部化，我们可以更灵活地调整系统行为，而无需修改核心代码。

配置文件通常采用 YAML (`.yaml` 或 `.yml`) 格式，因其易读性和对复杂数据结构的支持。

## 文件组织

*   **全局配置 (Global Configuration)**: (未来可能添加)
    *   例如 `global_config.yaml`，可能包含整个应用共享的设置，如日志级别、全局API密钥（如果适用且安全地管理）、通用服务地址等。
*   **模块特定配置 (Module-Specific Configuration)**:
    *   每个主要模块可以在此目录下拥有其独立的配置文件。
    *   命名约定：`module_<module_name>_config.yaml` (例如 `module_1_config.yaml` 用于文献与数据策略服务模块)。
    *   这些文件包含特定于该模块功能的参数，如API端点、过滤规则、默认参数、缓存设置等。

## 配置内容示例

模块的配置文件可能包含以下类型的信息：

*   **API 相关**:
    *   API 端点 URL。
    *   API 密钥的引用 (通常指向环境变量，例如 `api_key: "env:MY_MODULE_API_KEY"`)。
    *   默认的请求参数 (如重试次数、超时时间、回退因子)。
*   **业务逻辑参数**:
    *   启发式规则的阈值 (例如，最小样本数、允许的物种列表)。
    *   关键词列表。
    *   默认模型别名 (如果模块需要选择特定类型的LLM)。
*   **功能开关**:
    *   启用/禁用某些可选功能 (例如，`caching_enabled: true`)。
*   **缓存设置**:
    *   缓存的生存时间 (TTL)。
    *   缓存类型或后端服务的连接信息 (如果适用)。

## 使用方法

*   各个模块的服务类或组件在初始化时，会加载其对应的配置文件。
*   通常会有一个配置加载器工具或机制，用于解析 YAML 文件并将其内容提供给模块。
*   配置值应具有合理的默认值，以便在配置文件中未明确指定某些参数时，系统仍能正常运行。

## 注意事项

*   **安全性**: **绝对不要**将敏感信息（如实际的API密钥、密码）直接硬编码到配置文件中。始终使用环境变量引用 (如 `env:VARIABLE_NAME`) 或安全的密钥管理服务。
*   **清晰性**: 保持配置文件结构清晰、注释良好，以便于理解和维护。
*   **版本控制**: 将配置文件（不含敏感信息的模板或开发版本）纳入版本控制，以便跟踪更改。生产环境的配置文件应独立管理。
*   **中文注释**: 与项目整体要求一致，配置文件中的注释也应使用中文。
